## 1.1 도메인이란
* URL 주소 또는 도메인: 우리가 인터넷에서 웹사이트나 서비스를 쉽고 직관적으로 찾을 수 있게 해 주는 주소 체계
* 사람이 기억하기 쉬운 문자열 형식으로 구성되어 있으며, 실제 IP 주소를 대신해 사용됨.
* 도메인 등록 기관에서 등록 및 관리가 가능하며, DNS 시스템과 함께 작동하여 웹사이트 접속을 가능하게함

### IP 주소(Internet Protocol Address)
- 인터넷에 연결된 컴퓨터나 네트워크 장치가 서로를 식별하고 통신할 수 있도록 부여되는 고유한 주소
- 인간이 이해하기 편한 10진수 방식 선호

### DNS와 도메인
- ex) https://www.google.com
  - https: 프로토콜 이름
  - www: 호스트 이름
  - google: 도메인
  - com: 최상위 도메인
  - www.google.com: 전체 도메인 이름(Fully Qualified Domain Name)
* DNS(Domain Name System): 도메인 이름을 컴퓨터가 이해할 수 있는 IP 주소로 바꿔 주는 시스템

> 프로토콜
>> 서로 다른 국적의 사람이 대화하기 위해서는 통역이 필요하다. 네트워크도 동일한데, 이때 필요한 네트워크 상의 통신 규약을 의미한다. 서로 약속된 규칙(프로토콜)을 따라야만 정보 교환을 할 수 있다.

### 도메인의 종류
- 일반 최상위 도메인: 특정 국가와 관계없이 전 세계에서 공통으로 사용하는 도메인
  - .com: 상업적 용도. 기업, 쇼핑몰, 개인 사업자 등이 많이 선택
  - .org: 비영리 단체나 협회 등이 주로 사용
  - .net: 네트워크 인프라를 운영하는 회사들이 많이 사용
  - .info: 정보 제공 사이트에 적합
  - .biz: 비즈니스 관련 사이트에서 선호
- 국가 코드 최상위 도메인: 특정 국가를 상징하는 도메인. 각국 정부나 기업, 개인이 해당 국가 내에서 주로 사용. 지역성을 강조하고, 국내 사용자를 대상으로 하는 서비스에 신뢰성을 부여한다.
  - .kr: 대한민국의 국내 기업, 기관 개인이 공식적인 웹사이트 주소로 많이 사용
  - .jp: 일본
  - .us: 미국
  - .cn: 중국
### 도메인 등록 절차
1. 도메인 업체 접속
2. 도메인 검색
3. 사용 가능 여부 확인
4. 네임 서버 설정
5. 유지 관리

### 도메인 작동 방식
1. 사용자의 컴퓨터는 설정된 네임 서버(DNS 서버), 재귀적 네임 서버(Recursive Name Server)에 질의를 보낸다.
2. 네임 서버는 www.abc.com의 IP 주소를 알지 못하기 때문에, 컴퓨터에 IP 주소를 알려 주기 전에 다음과 같은 일련의 질의 과정을 거치게 된다.
3. 우선 인터넷 루트 서버에 질의하여 .com 최상위 도메인(TLD)의 네임 서버 정보를 얻는다.
4. .com TLD 네임 서버에 질의하여 abc.com 도메인의 권한 있는 네임 서버 정보를 얻는다.
5. abc.com 도메인의 권한 있는 네임 서버에 질의하여 마침내 www.abc.com 호스트의 IP 주소를 얻고 그 IP 주소를 컴퓨터에 반환한다.
6. 사용자의 컴퓨터는 www.abc.com의 IP 주소를 알게 되었으므로, 해당 호스트에 접속이 가능해진다.

# 2. 호스팅 영역 생성
* 호스팅 영역(Hosted Zone)은 Amazon Route 53에서 제공하는 DNS(Domain Name System) 관리의 핵심 구성 요소 중 하나로, 특정 **도메인 이름에 대한 DNS 레코드들을 체계적으로 관리하는 논리적인 공간**이다.
- 쉽게 말해, 호스팅 영역은 도메인 이름을 실제로 동작하게 만들기 위해 필요한 설정들을 저장하는 '주소록'과 같은 역할을 한다.
- 예를 들어, 사용자가 example.com이라는 도메인을 등록한 경우, 이 도메인을 웹 서버(IP 주소), 이메일 서버, 또는 CloudFront와 같은 AWS 서비스와 연결하려면 DNS 레코드(A 레코드, CNAME 레코드 등)를 설정해야 하는데,
이 작업이 바로 호스팅 영역 안에서 이루어진다.

## 2.1 Route 53
- Route 53: AWS에서 제공하는 고가용성, 확장성, 클라우드 기반 도메인 이름 시스템(DNS) 웹 서비스
- 이름에서 유추할 수 있듯이 DNS 표준 포트인 53번 포트에서 작동한다.
- 도메인 등록부터 DNS 라우팅, 헬스 체크까지 포괄적인 DNS 관련 기능을 제공해 주는 도메인 관리 서비스라고 할 수 있다.

## 2.2 호스팅 영역
### 레코드(Record)
* 특정 도메인 이름과 관련하여 수행하고자 하는 **동작 및 연결된 관련 정보들을 저장하고 있는 단위**

| 레코드 유형 | 설명               |     예시       |
|-------------|--------------------|--------------|
| A 레코드   | 도메인을 IPv4 주소에 연결 | example.com -> 19.5.0.5.44 |
| AAAA 레코드 | 도메인을 IPv6 주소에 연결 | example.com -> 2001:db8::1 |
| NS 레코드   | 도메인을 관리할 DNS 서버의 주소를 지정하는 레코드 |    |
| CNAME 레코드 | 도메인을 다른 도메인에 연결 | www.example.com -> example.com |
| ALIAS 레코드 | 도메인 -> AWS 리소스(예시: ELB, S3) Route 53 전용 |    |
| TXT 레코드   | 도메인 소유권 인증 |      |
| MX   | 이메일 서버 설정 | mail.example.com | 

### 호스팅 영역(Hosted Zone)
* 특정 도메인에 대한 **DNS 레코드를 저장하는 AWS Route 53의 컨테이너**
- 공개 호스팅 영역: 인터넷 사용자를 위하여 DNS 조회 처리를 하는 영역
- 프라이빗 호스팅 영역: VPC 내의 리소스에서만 접근이 가능한 영역. 내부 네트워크 전용

# 3. 인증서
* ACM 관리형 인증서(AWS Certificate Manager - Managed Certificate)는 웹 사이트나 애플리케이션에 TLS/SSL 암호화를 쉽게 적용할 수 있도록, **인증서의 발급, 갱신, 배포 과정을 자동화**하여 운영 부담을 줄여주는 매우 유용한 서비스로
  보안 접속(HTTPS) 구현 시 필수적인 요소이며, AWS 리소스와의 연동성이 뛰어나다.

## 3.1 인증서 개요
ACM은 Amazon이 관리해 주는 인증서로, 외부 인증 기관(CA)에서 수동 발급 받을 필요 없이 Amazon Trust Services에서 발급한다.

### ACM이 필요한 이유
ACM은 웹사이트와 사용자 간의 통신을 암호화하여 보안을 강화하고, 사이트의 신뢰성을 높이는 데 필수적이다.
HTTPS를 적용함으로써 데이터가 안전하게 전달되고, 브라우저에 아이콘이 표시되어 사용자는 사이트를 신뢰할 수 있게 된다. 또한, 기업이나 서비스 운영자는 관련 법률이나 보안 정책을 준수하기 위해 인증서를 반드시 적용해야 하는데,
ACM은 이를 자동으로 발급, 갱신해 관리 부담을 줄여 준다.

### SSL과 TLS
* SSL(Secure Sockets Layer)는 인터넷 환경에서 데이터를 안전하게 주고 받기 위해 처음 개발된 보안 프로토콜이다.
  사용자의 개인 정보나 결제 정보와 같은 중요한 데이터가 네트워크를 통해 전송될 때, 도청이나 변조를 방지하는 역할을 했다. 하지만 시간이 지나면서 여러 가지 보안 취약점이 발견되었고, 현재 더 이상 사용되지 않는다.
* TLS(Transport Layer Security)는 인터넷에서 **보안 통신을 보장하는 최신 프로토콜**이다.
  오늘날 우리가 접속하는 웹사이트의 https 통신을 비롯해, 이메일 전송 과정이나 VPN 연결, 그리고 다양한 애플리케이션 간의 API 통신 등 여러 영역에서 널리 활용되고 있다.
* 우리가 흔히 사용하는 "SSL 인증서"라는 표현도 실제로는 대부분 TLS 기반의 인증서를 의미한다.

### 인증서가 지원되는 AWS 리소스
AWS에서 인증서는 다음과 같은 리소스 항목들에서 지원된다.
- Elastic Load Balancing
- Amazon CloudFront
- Amazon API Gateway
- AWS Elastic Beanstalk
- Amazon Lightsail
- AWS App Runner
