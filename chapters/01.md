# 1. 서버/클라이언트 구조
## 1.1 서버와 클라이언트
* **클라이언트**: 서비스를 요청하는 사용자나 애플리케이션
* **서버**: 이 요청을 처리하고 결과를 반환하는 컴퓨팅 리소스(EC2, Lambda 등)

## 1.2 네트워크 통신
* **서버**: 가운데에서 원활히 데이터가 전송될 수 있도록 서비스하는 컴퓨터
* Client-Server 구조(CS 환경): 서버가 여러 클라이언트에서 넘어오는 데이터를 전달 받아서 다른 클라이언트에게 넘겨주는 것

## 1.3 서버의 종류
* **서버**: 무엇인가를 서비스하는 존재
- 웹 서버: 자원(HTML/이미지/동영상)에 대한 웹사이트의 기능을 제공 ex) Apache, Nginx 등
 - 메일 서버: 메일의 송수신과 메일 수신을 위한 서버 ex) Sendmail, Postifix 등
 - 데이터베이스 서버: 데이터를 검색해 주는 서버 ex) Oracle, MySQL, SQLite 등
 - 파일 서버: 파일을 저장하여 공유할 때 사용하는 서버 ex) Samba 등
 - FTP 서버: 파일을 업로드/다운로드 해 주는 서버

## 1.4 데이터 센터
* **데이터 센터**: 기업이나 특정 기관이 시스템과 데이터를 안전하고 효율적으로 운영, 관리하기 위해 구축한 시설
 - 서버, 저장 장치, 네트워크 장비, 전력 공급 장치, 냉각 시스템 등이 설치되어 있음
 - 대량의 데이터를 저장하고 처리하는 역할

### 데이터 센터의 문제점
1. 전력을 많이 소비하여 그만큼 에너지 비용이 든다.
2. 발열 및 냉각 문제
3. 구축과 유지에 드는 비용이 높다.
4. 보안 위협
5. 확장성의 한계: 데이터와 사용량이 급격히 증가하면, 물리적 공간이나 전력, 냉각 장치의 확장에 제한이 생길 수 있다.


# 2. 클라우드의 등장
* **클라우드 컴퓨팅**: 클라우드 환경에 구축된 서버, 스토리지, 네트워크, 데이터베이스 등의 인프라를 활용하는 방식, 또는 이를 기반으로 제공되는 서비스

## 2.1 가상화
* **가상화**: <U>하나의 물리적인 자원을 여러 개의 논리적인 자원으로 나누는 기술</U>. 즉, '하나의 컴퓨터(서버)를 여러 대인 것처럼 사용하는 기술'
* 구조
  - 가상 머신(Virtual Machines) 영역: 운영체제와 애플리케이션의 실행 환경 및 설정 정보, 그리고 저장 장치 등으로 구성됨
  - 가상화 계층(Virtualization Layer): 물리적 자원과 가상 머신 사이를 연결하는 가상화 소프트웨어(하이퍼바이저 등)
    - 가상 머신들이 물리 자원을 공유하게 보조하며, 자원(메모리, CPU 등)의 할당과 분리를 동적으로 관리하는 역할
    - 각 VM을 서로 격리시킴
  - 물리 서버(Physical Server): 물리적인 컴퓨터 자원들(CPU, 저장 장치, 메모리)
    - 실제 데이터 센터에 존재하는 하드웨어 서버
  * 가상화를 통해 하나의 물리적인 서버를 여러 개의 가상 서버로 분할하여 사용할 수 있으며, 사용자는 필요에 따라 즉시 서버를 생성하거나 제거할 수 있어 유연성과 확장성이 뛰어남.
 
## 2.2 리소스
* **리소스**: 사용자가 클라우드에서 생성하거나 사용하는 컴퓨터, 저장소, 네트워크, 데이터베이스 등의 서비스 요소.
  - ex) EC2 인스턴스, S3 버킷, RDS 데이터베이스, IAM 사용자 보안 그룹 등
즉, **AWS에서 사용자가 관리하거나 소비하는 모든 구성 요소가 리소스**가 될 수 있다.

## 2.3 클라우드 컴퓨팅
* **클라우드 컴퓨팅**: 인터넷을 통해 서버, 저장소, 데이터베이스, 네트워크, 소프트웨어 등의 컴퓨팅 자원을 필요할 때마다 제공받아 사용하는 기술
1. 자원 공유 및 인터넷 액세스(Resource Pooling * Broad Network Accsess)
    * 다수의 사용자들이 동일한 물리적 자원(서버, 저장소, 네트워크 등)을 공유하지만 가상화 기술을 통해 사용자마다 독립적이고 안전한 가상 환경을 제공함
    * 사용자들은 물리적인 하드웨어를 소유하거나 직접 설치하지 않아도, 필요한 시스템을 가상 환경에서 즉시 구축할 수 있음
    * 클라우드 서비스는 인터넷 기반으로 제공되기 때문에, 사용자는 시간과 장소에 관계없이 PC, 태블릿, 스마트폰 등 다양한 기기를 통해 언제든지 클라우드 자원에 접근하고 사용할 수 있음 (접근성 보장)
2. 주문형 서비스(On-Demand Self-Service)
    * 사용자가 필요한 순간에 즉시 자원을 요청하고 사용할 수 있는 환경 제공
    * 유연성 덕분에 초기 구축 비용이 크게 줄어들고, 사용한 만큼만 비용을 지불(Pay-as-you-go)하는 비용 효율적인 운영 가능   

### 클라우드 컴퓨팅의 장점
1. 비용 절감: 초기 비용이나 운영 비용 절감 가능.
    필요에 따라 리소스를 동적으로 할당하고 사용한 만큼만 지불함
2. 확장성과 유연(탄력)성: 특정 상황의 필요성에 따라 리소스를 탄력적으로 확장하거나 축소할 수 있어서 변동이 큰 워크로드에 유연하게 대응 가능
3. 속도 및 민첩성 향상: 여러 기술(컴퓨팅/스토리지/db/IOT/머신 러닝)에 대응하면서도 광범위하면서 신속하게 구축 가능
4. 데이터 집중화/통합 관리: 데이터를 중앙에서 통합하여 관리할 수 있어 데이터의 일관성과 효율적인 관리를 가능하게 하며, 협업과 데이터 공유를 원활하게 함.
5. 널리 사용되는 서비스: 세계 각지에서 서비스를 제공하므로 지리적으로 분산된 팀이나 사용자들 간에도 쉽게 협업 가능

# 3. 아마존 웹 서비스(AWS)
* Amazon.com에서 제공하는 세계 최대의 클라우드 컴퓨팅 플랫폼

## 3.1 One-Stop IT 인프라 제공
* 이전에는 서버, 데이터베이스, 운영 체제(OS), 보안 등을 별도 업체에서 각각 구매하거나 임대하여 사용했으나 AWS에서는 필요한 모든 인프라 자원을 한번에 선택하고 관리할 수 있음
* 서버, 운영 체제, 웹 서버, 데이터베이스 등 필요한 모든 요소를 한 번에 구성하고 사용할 수 있는 통합 환경 제공

## 3.2 AWS의 특징
* IT 인프라에 필요한 다양한 서비스를 하나의 플랫폼에서 함께 제공하는 **종합 서비스 플랫폼**
* **종량제 시스템**: Pay-as-you-go 방식으로 운영되어 초기 구축 비용 없이 필요한 만큼만 사용하고, 그에 따른 비용만 지불하며 자원의 효율적인 사용과 비용 관리에 큰 이점을 제공
* **글로벌 인프라**: 전 세계 여러 지역에 리전(Region)과 가용 영역(Avail ability Zone)을 운영하여 높은 가용성을 유지하고, 사용자에게 낮은 지연 시간으로 안정적인 서비스 제공
* **확장성과 유연성**이 뛰어나 필요에 따라 자원을 신속하게 확장하거나 축소할 수 있음
* 물리적 보안, 네트워크 보안, 데이터 암호화 등 강력한 보안 기능을 제공하여 높은 신뢰성과 안전성 보장

### AWS 임대 방식
* 정액제 임대 방식: 사용자가 서비스의 사용량과 관계없이 매월 일정한 금액을 지불하는 방식
* 종량제 임대 방식: 사용자가 사용한 양에 따라 요금이 부과되는 방식. 사용한 만큼만 비용을 지불하므로, 자원을 효율적으로 사용할 수 있으나, 사용량이 갑자기 많아지면 비용이 급격히 증가할 수 있음

## 3.3 AWS의 주요 서비스와 특징
* 컴퓨팅
  * Amazon EC2(Elastic Compute Cloud): 클라우드에서 가상 서버를 띄워 원하는 OS, 인스턴스를 선택해 쓰고, 트래픽에 따라 서버 수를 탄력적으로 조정할 수 있는 핵심 컴퓨팅 서비스
  * AWS Lambda: 서버를 직접 관리하지 않고, 이벤트가 발생했을 때 코드만 실행하는 서버리스 컴퓨팅 서비스
* 스토리지(Storage)
  * Amazon S3 (Simple Storage Service): 이미지, 문서, 로그, 백업 등 각종 파일을 저장하는 고내구성 객체 스토리지 서비스
  * Amazon EBS (Elastic Block Store): EC2 인스턴스에 붙여 쓰는 블록 스토리지로, 운영체제나 데이터베이스 저장용으로 적합하며 SSD/HDD 등 다양한 성능 옵션 제공
* 데이터베이스(Database)
  * Amazon RDS (Relational Database Service): MySQL, PostgreSQL, Oracle, SQL Server 등 관계형 DB를 완전관리형으로 제공하여 백업, 패치, 확장 작업을 자동으로 처리해 주는 서비스
  * Amazon DynamoDB: 밀리초 단위 응답 속도와 자동 스케일링을 제공하는 완전관리형 NoSQL 데이터베이스
* 네트워킹 및 콘텐츠 전송(Networking & Content Delivery)
  * Amazon VPC (Virtual Private Cloud): AWS 상에 독립된 가상 네트워크를 구성해 서브넷, 라우팅, 보안 그룹 등을 직접 설계, 관리할 수 있게 해주는 서비스
  * Amazon Route 53: 도메인 이름을 관리하고, 웹 트래픽을 적절한 리소스로 라우팅하는 관리형 DNS 서비스
 
## 3.4 AWS의 글로벌 인프라
* 하나의 리전은 두 개 이상의 가용 영역으로 구성되어 있음
### 리전
* 클라우드 서비스를 제공하기 위해 물리적인 자원이 모여 있는 데이터 센터의 지리적인 위치
  * AWS가 전 세계에 설치한 대규모 물리적 서버 인프라가 위치한 장소
  * 일반적으로 사용자 가까이에 있는 리전을 선택하면 빠른 응답 속도와 법적 안정성을 확보할 수 있음
* 리전 선택 시 고려해야 할 사항
  * 지연 속도(Latency): 사용자와 가까운 리전을 선택하면 응답 속도가 빨라진다.
  * 법률 및 규제: 데이터가 저장되는 위치는 국가별로 법적 규제를 받을 수 있음
  * 서비스 가용성: 모든 AWS가 모든 리전에서 제공되지는 않으므로 필요한 서비스가 선택하려는 리전에서 제공되는지 반드시 확인해야 함
  * 요금: 리전마다 요금이 다를 수 있음
### 가용 영역(Availability Zone, AZ)
* 리전의 하위 개념으로, 실제 데이터를 저장하고 서비스가 운영되는 물리적인 데이터 센터를 의미함
* 각 리전은 두 개 이상의 가용 영역으로 구성되어 있으며, 이 가용 영역들은 서로 물리적으로 분리된 독립적인 위치에 존재함
* 구조적 특징
  * AZ는 하나 이상의 실제 데이터 센터(IDC)로 구성되며, 해당 센터는 전력, 냉각, 네트워크 등의 자원을 독립적으로 갖추고 있어 하나의 AZ가 장애를 겪더라도 다른 AZ에서 서비스가 계속 제공될 수 있도록 설계됨
  * 각 AZ는 일정 거리 이상 떨어져 있어 자연 재해, 정전, 테러 등의 리스크로부터 물리적으로 분리되어 있으며너도, 낮은 지연(latency)를 위해 일반적으로 수 킬로미터(km) 이내 거리에 위치함
* 역할과 이점
  * 하나의 AZ에서 장애가 발생하더라도, 다른 AZ에서 자동으로 서비스를 이어받을 수 있어 높은 가용성 보장
  * 기업은 애플리케이션과 데이터를 여러 AZ에 분산 배치하여 장애 복구(DR, Disaster Recovery) 전략을 효율적으로 구성할 수 있음
  * 같은 리전 내의 AZ들은 AWS의 고속 전용 네트워크로 연결되어 있어 빠르고 안정적인 데이터 통신 가능

> Transit Center
>> 리전에서 외부 인터넷과 통신 시 Transit Center를 거친다.
>> Transit Center는 인터넷과 AWS 내부 네트워크를 연결하는 핵심 노드로서, 트래픽을 효율적으로 처리한다.
