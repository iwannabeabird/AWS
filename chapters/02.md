# 1. 네트워크 구성 개요
## 1.1 아키텍처 구성
* VPC
* Subnet
* 인터넷 게이트웨이: VPC와 외부 인터넷 간의 트래픽을 주고 받을 수 있도록 연결해주는 리소스
* 라우팅 테이블: 네트워크 안에서 트래픽이 어떤 경로를 통하여 데이터를 목적지까지 이동시킬 것인지를 알려주는 내비게이션 역할
* 프로토콜: 컴퓨터나 네트워크 장치끼리 통신하기 위한 약속 또는 규칙

> 프로토콜의 종류
>>1. HTTP: 웹 브라우저와 웹 서버가 페이지를 주고 받는 규칙
>>   - 주소창에 http://로 시작하는 프로토콜
>>2. HTTPS: HTTP에 보안(암호화) 기능이 추가된 프로토콜
>> - 요즘 대부분의 웹사이트가 사용하는 프로토콜
>>3. FTP: 파일을 전송할 때 사용하는 프로토콜
>>4. SMTP/IMAP/POP3: 이메일을 주고받는 프로토콜
>>5. TCP/UDP: 데이터 전송 방식을 정의한 프로토콜
>> - TCP: 안정적(순서 보장), UDP: 빠름(실시간 스트리밍에 사용)

* 보안 그룹: 퍼블릭 서브넷에서 인스턴스가 외부와 안전하게 통신할 수 있도록 인바운드(수신) 트래픽에 대한 접근 제어 규칙 정의

# 2. VPC
사용자가 정의하는 나 자신만의 가상 네트워크 
사용자는 VPC 내에서 리소스를 실행할 수 있으며, **AWS의 데이터 센터 내에서 완전히 격리된 환경을 제공**함

## 2.1 네트워크
두 대 이상의 컴퓨터나 장치들이 서로 데이터를 주고 받을 수 있도록 연결된 구조

## 2.2 VPC
* AWS에서 논리적으로 격리된 가상 네트워크로 VPC를 제공함
- 해당 VPC 내에서 자신의 리소스(EC2, RDS 등)를 배치하고, 서비스를 제공함.

> VPC 관련 주요 용어
>> - VPC(Virtual Private Cloud): 사용자가 정의하는 독립적인 네트워크 환경
>> - 서브넷(Subnet): VPC 내에서 논리적으로 분리된 네트워크 영역
>> - 라우팅(Routing): 네트워크 트래픽 경로 관리자
>> - 인터넷 게이트웨이(IGW): 인터넷과 통신하기 위한 출입문 역할
>> - 보안 그룹과 네트워크 ACL: 보안 그룹(인스턴스 수준의 방화벽), 네트워크 ACL(서브넷 수준의 방화벽)

### 리전과 VPC
- 하나의 VPC는 특정 리전에만 존재하며, 다른 리전과는 연결되지 않음.
- 한 개의 리전에는 여러 개의 VPC가 있을 수 있음

> VPC의 특징
>> VPC는 각각의 리전마다 독립적으로 구성할 수 있으며, 여러 개의 VPC를 생성할 수 있다.
>> 독립적으로 구성된 VPC는 필요에 의하여 서로 연결시키면 네트워크 확장이 가능하다.
>> VPC는 AWS 리소스(EC2 인스턴스, RDS 데이터베이스 등)를 배치하는데 사용된다.

# 3. 인터넷 게이트웨이
VPC는 프라이빗 클라우드를 위한 독립 네트워크 환경으로, 기본적으로 외부 인터넷과는 연결되어 있지 않다..
외부와의 통신이 필요할 때는 인터넷 게이트웨이를 통해 데이터를 주고받는다.
이를 통해 내부 네트워크가 인터넷에 접근하거나, 외부에서 내부로의 접근을 허용할 수 있다.

## 3.1 인터넷 게이트웨이 개요
* 가상 네트워크의 내부 리소스가 공용 인터넷과 통신할 수 있도록 해주는 가상 라우터
- 즉, 프라이빗 네트워크가 퍼블릿 인터넷으로 나가거나 또는 퍼블릭 인터넷이 프라이빗 네트워크로 들어오게 하려면 반드시 필요한 개념

# 5. 서브넷
* 서브넷(Subnet): VPC라는 하나의 가상 네트워크 환경 안에서 IP 주소 범위를 논리적으로 나누어, 각기 다른 작은 네트워크 영역을 정의하는 단위
- VPC는 매우 넓은 범위의 IP 주소들을 포함하는 큰 네트워크이고, 서브넷은 그 안에서 서로 다른 목적이나 요구 사항에 맞게 구획을 나누어 운영할 수 있도록 하는 작은 네트워크 단위
- 네트워크 트래픽을 효율적으로 관리하고, 보안, 성능, 그리고 다른 네트워크 리소스의 구성을 세밀하게 제어할 수 있음

## 5.1 서브넷 개요
- 하나의 VPC 영역에 여러 개의 가용 영역이 포함되어 있으며, 하나의 가용 영역에 여러 개의 서브넷이 포함될 수 있다.

> 서브넷의 특징
>> 1. VPC 내 별도로 만들어진 작은 네트워크
>> 2. 반드시 하나의 AZ에 종속적으로 위치함
>> 3. 네트워크 환경 구성에 따라서, 퍼블릭과 프라이빗으로 구분됨

### IP 주소
- 네트워크에 연결된 장치(컴퓨터, 스마트폰, 서버 등)를 구분하기 위한 고유한 주소

#### IP 버전
 - IPv4: 32비트 주소 체계를 사용하여 약 43억 개의 주소를 제공하며 주소 형식은 점(.)으로 구분된 10진수 4개 형식이다. ex) 192.168.0.1
 - IPv6: 주소 부족 문제를 해결하기 위해 도입됨. 128비트 주소 체계를 사용하여 사실상 무한에 가까운 수의 IP 주소를 제공하며, 보안성과 효율성이 향상된 것이 특징

#### IP 할당 방식
- 고정 IP 주소: 한 번 할당되면 변경되지 않고 항상 동일한 주소를 사용하는 방식
  - 서버나 네트워크 장비처럼 항상 같은 주소로 접근해야 하는 시스템에서 주로 사용
- 유동 IP 주소: 네트워크에 접속할 때마다 DHCP 서버에 의해 임시로 할당되며, 접속할 때마다 주소가 바뀔 수 있음
  - 일반 가정용 인터넷이나 이동 통신망에서는 대부분 유동 IP 방식을 사용
> DHCP 서버(Dynamic Host Configuration Protocol Server)
>> 네트워크에 연결된 클라이언트(컴퓨터, 스마트폰, 프린터 등)에게 자동으로 IP 주소와 네트워크 서렁 정보를 할당해 주는 서버

#### 통신 용도
- 퍼블릭 IP 주소: 인터넷 상에서 고유하게 식별되는 주소, 외부 네트워크와 직접 통신할 수 있음
- 프라이빗 IP 주소: 내부 네트워크(가정, 회사 등)에서만 사용되는 주소로 외부 인터넷과 직접  통신할 수 없으며, NAT 기술을 통해 공인망과 연결됨

> NAT(Network Address Translation, 네트워크 주소 변환)
>> 내부(사설) 네트워크의 IP 주소를 외부(공인) 네트워크에서 사용할 수 있도록 IP 주소를 변환하는 기술
>> 하나의 공인 IP 주소로 여러 장치가 인터넷을 공유할 수 있게 해 주는 기술

#### IP CIDR
* CIDR 표기법(Classless Inter-Domain Routing): 인터넷의 크기가 커짐에 따라 클래스 단위의 IP 주소 할당은 라우팅 테이블을 복잡하게 하고, 인터넷 주소 공간을 낭비하는 문제를 개선하기 위해
클래스에 제한을 두지 않고 **필요한 컴퓨터의 수에 따라 적당한 크기의 IP 주소를 할당하는 방식**
* IP 주소와 서브넷 마스크를 함께 간결하게 표현하기 위한 방식으로 네트워크를 분할하거나 IP 주소를 효율적으로 관리하는 데 사용됨
- CIDR 표기: IP주소/Prefix길이
* ex) 10.250.1.0/24
  - IPv4 주소는 32비트(4바이트)이며, 일반적으로 4개의 10진수 옥텟으로 표현된다. 10.250.1.0 -> 32비트가 된다. '10.250.1.0/24'는 앞 24비트가 네트워크 주소, 나머지 8비트가 호스트 주소가 된다.
    - 네트워크 주소: 해당 IP가 속한 네트워크 자체를 식별하는 데 사용됨. 즉, 동일한 공간 내에 있는 컴퓨터들의 네트워크 주소가 동일함
    - 호스트 주소: 동일한 네트워크 내부에서 개별 장치(호스트)를 식별하는 데 사용됨. 즉, 동일한 공간 내에 있는 모든 컴퓨터들은 고유한 호스트 주소를 가져야 함.

# 6. 라우팅 테이블
* 컴퓨터나 라우터가 데이터 패킷을 어느 경로로 전송해야 할지 결정하기 위한 테이블

## 6.1 라우팅 테이블의 역할
- 네트워크에서 데이터 전송 시, 해당 데이터 패킷이 최적의 경로를 통해 목적지에 도달할 수 있도록 결정하는 중요한 역할
- **컴퓨터나 라우터가 패킷의 목적지 IP 주소에 맞는 경로를 찾아내기 위해 참조하는 데이터 구조**

### 라우팅 테이블의 필요성
* 컴퓨터 수가 많아질수록 각 기기 간 연결이 기학급수적으로 늘어나 설치와 관리가 어려워지는데, 이 문제를 해결하기 위해 **라우터(router)**가 사용된다.
- 라우터는 서로 다른 네트워크 간의 통신을 중개하여 복잡한 연결을 효율적으로 관리하고, 네트워크의 혼잡도를 줄여 원활한 데이터 흐름을 가능하게 한다.
  - "데이터를 어디로 보내야 할지를 결정"해주는 역할. 즉, 네트워크 안에서 통신 데이터를 보낼 때 최적의 경로를 선택하는 프로세스 또는 과정
- 라우팅 테이블: 이러한 장치가 "어떤 데이터를 어디로 보낼지를 정의해 놓은 관리 장부

### 라우팅 테이블
- 출발지에서 목적지로 가는 여러 경로 중 최적의 경로를 관리하고 선택하는 시스템

> * 라우팅: 네트워크 트래픽을 조절하는 기능
> * 라우터: 라우팅 수행 장비
> * 라우팅 테이블: 네트워크 트래픽의 경로 정보를 저장해 놓은 장부

### 가상 라우터와 라우팅 테이블
* 가상 라우터: 소프트웨어 기반의 라우팅 기능을 수행해 주는 장치로 실제로 경로를 선택하고 전달하는 역할
* 라우팅 테이블: 그 가상 라우터가 잠고하는 데이터 목록

# 8. 보안 그룹
* AWS에서 웹 서버(EC2 인스턴스 등)와 같은 리소스를 보호하기 위해 사용되는 가상 방화벽(Virtual Firewall) 역할
* 인스턴스로 들어오는(Inbound) 트래픽과 나가는(Outbound) 트래픽에 대해 세밀하게 제어할 수 있는 방화벽 규칙의 집합

## 8.1 보안 그룹 개요
- 사용자는 허용하고자 하는 IP 주소, 포트 번호, 프로토콜 등을 지정함으로써, 외부에서 인스턴스로 접근할 수 있는 경로를 안전하게 제한할 수 있음
- 기본적으로 모든 트래픽은 차단되며, 명시적으로 허용된 트래픽만 통과할 수 있음
- 인스턴스를 배포한 후에도 자유롭게 수정 가능하며, 하나의 인스턴스에 여러 개의 보안 그룹을 적용할 수 있어, 역할 기반 보안 설정도 유연하게 구성할 수 있음
- 보안 그룹은 상태 저장(Stateful)이기 때문에, 인바운드 규칙으로 들어온 트래픽에 대해서 자동으로 응답 아웃바운드가 허용됨

### 방화벽
* 보안 그룹과 네트워크 ACL이라는 네트워크 보안 기능은 모두 **외부에서 내부로 들어오는 트래픽 또는 내부에서 외부로 나가는 트래픽**의 접근을 제어하는 역할을 하며, 일종의 가상 방화벽처럼 작동함
#### 공통점
1. AWS에서 제공하는 가상 방화벽 기능(검문소 역할)
2. 트래픽에 대한 접근을 통제(허용/거부)할 수 있음
3. 보안 규칙을 만들기 위하여 IP 주소 범위, 포트 범위, 프로토콜 등 사용
4. 보안 규칙은 인바운드(Input Traffic)와 아웃바운드(Output Traffic)의 방향성이 있음

| 항목                 | 보안 그룹 (Security Group) | 네트워크 ACL (Network ACL) |
| -------------------- | -------------------------- | --------------------------- |
| 트래픽 접근 제어 대상 | 인스턴스                   | 서브넷  |
| 상태                 | Stateful                   | Stateless |
| 허용 및 거부 정책    | 허용이 아닌 항목은 모두 거부 | 허용과 거부 목록을 따로 가지고 있음 |

### 허용 및 거부 정책
* 보안 그룹: 허용하고자 하는 규칙만 나열하며, 명시하지 않은 규칙은 모두 거부 대상
* 네트워크 ACL:  허용 규칙과 거부 규칙이 모두 존재하며, 순차적으로 확인하여 허용과 거부를 판단함
* 보안 그룹은 인스턴스 보안을 간단하게 설정할 수 있는 장점이 있고, 네트워크 ACL은 보다 정교한 네트워크 접근 제어가 필요한 경우에 유용하게 사용됨

## 8.3
### 인바운드/아웃바운드 규칙
* 인바운드 규칙: 외부에서 EC2 인스턴스 등 **AWS 리소스로 들어오는 네트워크 트래픽을 제어**하는 설정
  * 어떤 IP 주소나 IP 대역이, 어떤 프로토콜과 포트를 사용해서, 어떤 방식으로 접속할 수 있는지를 세부적으로 지정할 수 있음
* 아웃바운드 규칙: 인스턴스가 외부로 나가는 트래픽을 제어하며 기본적으로 모든 아웃바운드 트래픽은 허용되어 있음

### 포트 번호
* 네트워크 트래픽은 인바운드와 아웃바운드 각각 포트 단위로 접속 허가 여부를 설정함
* 포트(Port): 네트워크 통신을 위한 입구로써, 숫자 형식으로 지정함

| 포트 번호 | 서비스 | 내용             |
| ----------- | -------- | -------------- |
| 80           | HTTP  | 웹 송수신|
| 443         | HTTPS | 웹 송수신 |
| 22         | SSH   | SSH 통신|
| 1521       | Oracle DB | 오라클 DB 통신 |
| 3306       | MySQL   | MySQL DB 통신 |
