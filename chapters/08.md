# 1. Terraform 소개
- 인프라 자동화(Infrastructure as Code, IaC): 운영자가 직접 콘솔에 접속해 서버를 생성하거나 네트워크를 연결하는 대신, 코드로 인프라를 정의하고 실행하여 동일한 결과를 얻을 수 있게 함

> 인프라
>> - 컴퓨터와 네트워크 환경에서 서비스를 운영하기 위해 필요한 기반 환경 전체
>> - 소프트웨어가 돌아가기 위해 필요한 하드웨어, 네트워크, 서버, 스토리지, 데이터베이스, 로드 밸런서, 보안설정 등 모든 것을 포함하는 개념
>> - Terraform은 이러한 인프라 자동화를 대표하는 도구 중 하나로, 여러 클라우드 서비스(AWS, Azure, GCP, OCI 등)를 HCL이라는 단일 언어로 제어할 수 있다.

## 1.1 인프라 자동화란?
- 서버, 네트워크, 스토리지, 보안 설정 등 IT 인프라를 사람이 수동으로 구성하지 않고 코드를 사용하여 관리하는 방식
- 이를 통해 반복 작업을 자동화하고, 일관성을 유지하며, 오류를 줄일 수 있다.
- 예를 들어 가상 머신 생성, 로드 밸런서 구성, 방화벽 규칙 설정 등이 있으며, 이러한 작업을 코드로 정의하고 실행함으로써 빠르고 신뢰성 높은 인프라 운영이 가능해진다.
- 인프라 자동화는 DevOps 문화의 핵심 요소 중 하나로, 개발과 운영의 경계를 허물고 협업을 촉진하는 기반이 된다.

> DevOps
>> 개발(Development)와 운영(Operations)의 경계를 허물고, 소프트웨어 개발과 시스템 운영 간의 협업과 자동화 및 지속적인 개선을 통해 빠르고 안정적인 서비스를 제공하기 위한 조직 문화를 의미한다.
>>

## 1.2 Terraform이란?
- Terraform: HashiCorp에서 개발한 오픈 소스 인프라 자동화 도구로, 코드 기반으로 클라우드 인프라를 정의하고 배포할 수 있도록 지원한다.
- 사용자는 HCL(HashiCorp Configuration Language)이라는 선언적 언어를 사용해 인프라 리소스를 기술하며, 이 코드를 통해 클라우드 리소스를 일관되게 생성, 수정, 삭제할 수 있다.
- AWS, Azure, Google Cloud, Oracle Cloud Infrastructure(OCI) 등 다양한 클라우드 서비스를 지원하므로, 멀티 클라우드 및 하이브리드 클라우드 환경에서도 강력한 도구이다.

## 1.3 Terraform의 장점
1. **인프라를 코드로 관리**할 수 있다. 인프라 구성을 코드화함으로써 버전 관리가 가능해지고, 여러 개발자 간 협업이 용이해지며, 구성 요소를 재사용 할 수 있다.
2. **플랫폼 독립성을 제공**한다. 다양한 클라우드 제공자와 연동할 수 있어 특정 벤더에 종속되지 않고, 필요에 따라 여러 환경에서 동일한 코드를 활용할 수 있다.
3. **선언적 구성**(Declarative Configuration): 사용자가 원하는 인프라 상태를 기술하면, Terraform이 현재 상태를 분석하여 필요한 변경만 자동으로 수행하므로 불필요한 수작업을 줄일 수 있다.
4. **계획과 적용의 분리 기능**을 통해 실행 전 변경 사항을 사전에 확인할 수 있어, 예기치 못한 리소스 변경이나 오류를 예방할 수 있다.
5. **모듈화 및 재사용성**을 제공하여 반복적으로 사용되는 리소스 구성을 모듈화하면, 다른 프로젝트에서도 손쉽게 재사용할 수 있어 효율적인 인프라 관리를 가능하게 한다.

## 1.4 Terraform 구성 요소
- Provider + Resource + Module + Variable = Terraform

### 프로바이더
- Terraform이 어떤 클라우드 환경 또는 인프라 플랫폼과 상호 작용할 지를 정의한다.
- 프로바이더는 Terraform이 각 플랫폼의 API를 호출해 리소스를 생성하거나 수정할 수 있도록 연결하는 역할을 한다.

### 리소스
-실제 인프라에서 생성되거나 관리되는 개별 단위
- ex. EC2 인스턴스, S3 버킷, VPC, 서브넷 등이 리소스로 표현된다.
'
### 모듈 
- 리소스들의 집합을 하나의 논리 단위로 묶음 구성
- 공통된 인프라 구성(VPC, 서브넷 세트 등)을 모듈로 정의해 두면, 여러 프로젝트에서 재사용할 수 있어 코드의 중복을 줄이고 유지 보수를 용이하게 한다.

### 베리어블
- Terraform 코드에서 값을 동적으로 처리할 수 있도록 도와 주는 요소
- 하드 코딩을 피하고 다양한 환경에 맞게 설정값을 바꿀 수 있도록 하기 위해 사용
- 리전(region), 인스턴스 타입(instance type), 태그(tag) 등을 변수로 지정하여 코드의 유연성을 높인다.
