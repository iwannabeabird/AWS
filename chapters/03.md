# 1. 인스턴스 개요
* EC2: 클라우드 환경에서 가상 서버(Virtual Server)를 제공하는 대표적인 서비스

## 1.1 임대 서버와 클라우드
| 항목 | 임대 서버 | 클라우드 서버(EC2 등) |
|---|---|---|
| 서버 구성 방식 | 이미 구성된 서버를 임대 | 사용자가 직접 구성(CPU, 메모리, OS 등 선택) |
| 유연성 | 낮음(구성 변경 불가 또는 제한적) | 높음(필요에 따라 자유롭게 변경 가능) |
| 설치 및 초기 설정 | 대부분 사전 설정 완료 | 사용자가 직접 설치 및 설정 |
| 확장성 | 물리적 한계 존재 | 버튼 클릭만으로 탄력적 확장 가능 |
| 관리 주체 | 제공 업체가 대부분 관리 | 인프라는 AWS가, 소프트웨어는 사용자가 관리 |
| 비용 구조 | 일정 기간 고정 요금 | 사용한 만큼 과금(On-Demand)되는 종량제 |
| 운영 편의성 | 기본 환경 제공으로 간편 | 처음은 어렵지만 학습 후 훨씬 더 유연한 운영 가능 |

## 1.2 하드웨어적인 작업과 소프트웨어적인 작업
### 하드웨어적인 작업 차이점
* 비클라우드 환경
  * 서버 관리자가 물리적으로 데이터 센터나 서버가 설치된 장소에 직접 방문해야 함
  * 서버의 조립, 운영 체제 설치, 하드웨어 점검, 네트워크 장비 연결 등 다양한 하드웨어적인 작업을 수작업으로 처리해야 하며, 이에 따른 시간과 인력, 비용이 발생함
* 클라우드 환경
  * 관리 콘솔(Management Console)이나 CLI(Command Line Interface)를 통해 웹 브라우저 상에서 서버 인스턴스를 생성하고, 필요한 리소스를 설정함
### 소프트웨어적인 작업 공통점
* 서버가 준비된 이후 패키지 설치, 환경 설정, 코드 배포 등 모두 원격 접속 방식으로 이루어짐

## 1.3 EC2 인스턴스
* Amazon EC2(Elasitc Compute Cloud): 사용자가 서버(인스턴스)를 생성하여 애플리케이션을 실행할 수 있도록 해주는 서비스

### EC2 주요 특징
1. **필요한 시점에 원하는 만큼 서버를 사용**할 수 있는 유연한 인프라 환경 제공
2. 다양한 인스턴스 타입을 제공하여, 웹 서버, 데이터베이스, 머신 러닝 등 **특정 작업 목적에 맞는 서버 사양을 선택**할 수 있음.
3. 보안 그룹(Security Group), VPC(Virtual Private Cloud) 등 다양한 네트워크 및 보안 관리 도구를 제공하여, 사용자가 직접 **데이터 접근 권한과 네트워크 트래픽을 제어**할 수 있음
4. 초기 비용 없이 **사용한 만큼만 지불**하는 구조

### EC2 구성 요소
- 인스턴스(Instance): 클라우드에서 실행되는 가상 머신 서버
- AMI(Amazon Machine Image): 인스턴스 생성에 필요한 이미지 템플릿(자주 사용하는 운영체제를 템플릿 형태로 제공)
- 키 페어(Key Pair): 접속 시 필요한 인증(Authentication) 정보를 가진 키-값 쌍
- EBS: 인스턴스에 사용되는 스토리지(Storage)
- 보안 그룹: 가상 방화벽(트래픽 검문소)
- 탄력적 IP: 고정 IPv4 주소

### EC2 장점
#### 1. 간편한 생성 절차
AWS 관리 콘솔을 통해 인스턴스를 손쉽게 생성할 수 있다.
#### 2. 다양한 사양과 운영 체제 선택 가능
사전에 준비된 AMI를 통해 다양한 운영체제(Ubuntu, Windows, Amazon Linux 등)를 선택할 수 있으며, 인스턴스 유형 또한 CPU, 메모리, 네트워크 성능에 따라 자유롭게 구성할 수 있다.
#### 3. 유연한 변경 및 확장성
컴퓨터 동작 중에도 필요하다면 인스턴스 유형을 업그레이드 하거나 디스크 용량을 확장할 수 있다. 
#### 4. 다양한 성능 사양의 인스턴스 선택 가능
CPU 성능과 메모리 용량이 서로 다른 다양한 인스턴스 유형을 제공하고 있어, 자신의 애플리케이션에 맞는 최적의 사양을 선택할 수 있음

# 2. 키 페어
* EC2 인스턴스에 안전하게 접속하기 위한 인증 수단

## 2.1 SSH
* 네트워크를 통해 다른 컴퓨터에 안전하게 접속하게 해 주는 프로토콜
- 주로 EC2 인스턴스와 같은 원격 서버에 명령어를 입력하거나 파일을 전송할 때 사용됨

## 2.2 SSH 서버
* SSH는 주로 리눅스나 유닉스 계열에서 사용되며, 서버 관리자가 원격에서 명령어를 실행하거나 시스템을 유지/보수 하는데 필수적이다.
* 리눅스 환경에서는 OpenSSH가 기본 포함되어 있어 별도 설치 없이 바로 사용할 수 있다. 
* 반면, Windows는 기본적으로 SSH 서버를 제공하지 않지만, SSH 클라이언트를 설치하면 원격 서버에 접속해 명령어 실행이나 파일 전송이 가능하다.
* 대표적인 SSH 클라이언트로는 Putty, Xshell, MobaXTerm 등이 있다.

## 2.3 키 페어 개요
- 키 페어는 비대칭암호화 방식을 이용하며, 두 개의 키(공개 키와 비밀 키)로 구성된다.
- AWS는 공개키를 저장하고, 사용자는 키밀 키(Private Key)를 통해 인스턴스에 SSH로 접속한다.

> 키 페어의 특징
>> 공개 키(Public Key)는 클라우드 인스턴스에 저장된다.
>> 비밀 키(Private Key)는 사용자가 보관하며, 인스턴스에 접근 시 SSH 클라이언트와 함께 사용하여 인증이 이루어진다.
>> 하나의 키 페어는 리전끼리 공유가 불가능하다.

## 3.7 탄력적 IP
EC2 인스턴스는 **인스턴스를 중지하거나 재시작 시 이전에 할당되었던 공인 IP 주소가 변경**된다.
만약 해당 인스턴스를 웹 서비스를 제공하는 서버로 사용 시, 이러한 현상은 매우 심각한 문제가 될 수 있다.

### 재시작 시 IP 주소 변경
탄력적(Elastic) IP: 특정 인스턴스에 *고정된 IP*를 할당하여, 재부팅 후에도 동일한 IP 주소를 유지할 수 있도록 해줌.

#### 탄력적 IP의 특징
* IP 주소 유형: 고정 공인 IP
* 연결 대상: EC2 인스턴스 또는 네트워크 인터페이스
* 변경 여부: 인스턴스를 중지/재시작 해도 IP 주소 유지
* 과금 정책: 연결된 상태이면 무료, 미연결 시 과금
* 개수 제한: 기본 5개(추가 요청 가능)

### IP 재할당
**탄력적 IP**(Elastic IP, EIP)는 특정 인스턴스에 종속되지 않고, AWS 계정에 귀속되는 **고정 IP 주소**이다.
EC2 인스턴스를 삭제하더라도, 해당 인스턴스에 할당되어 있던 탄력적 IP는 계속해서 해당 AWS 계정의 소유로 남아 있으며, 이후 다른 인스턴스에 재할당하여 사용할 수 있다.

### 탄력적 IP의 필요성
1. 웹사이트에 **도메인 연결 시 고정 IP가 필요**하다.
  - EC2 인스턴스를 재시작하거나 교체하더라도 동일한 IP 주소를 유지할 수 있어, 도메인과의 연결이 끊기지 않는다.
2. **외부 시스템에서 내 EC2 서버로 접근 시 고정 IP 주소가 필요**하다.
  - 외부 API 서버와의 연동 시에도 중요하다.
  - 외부 서비스가 언제나 동일한 IP를 통해 내 서버에 접근 할 수 있어, 인증 및 통신이 안정적으로 이루어진다.
3. **새로운 EC2 인스턴스로 교체해야 하는 상황**이 발생하더라도, 기존 탄력적 IP를 새 인스턴스에 재연결하기만 하면 동일한 IP 주소를 유지할 수 있다.
  - 서버 변경 과정에서도 서비스 중단 없이 연속하여 운영이 가능하다.

## 과금 주의 사항
탄력적 IP는 유휴 상태면 과금되므로 꼭 EC2에 연결하거나, 필요 없을 땐 반드시 해제한다.
